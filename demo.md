# Demo run sheet

A run sheet, not a pitch deck. Read it once before the call. Follow it during the last five minutes.

## Before the call, 3 minutes

1. Copy the manager's likely function (ops or gtm) and stack into a fresh intake file named after their company.
2. Run generate.
3. Run check.
4. Open 00-case-brief.md and 03-pair-bonus.md in a viewer.
5. If nothing is known about their stack, use the matching sample pack (acme-ops for ops, northwind-gtm for gtm) instead, and say so on the call.

## The two sentences

Say this, exactly, then stop talking:

"I'm putting together a working session for teams like yours. Their own tools, their own work, a scenario built from a short conversation with the manager, everyone in the room together. Would you want to be one of the first teams to try it?"

Stop talking.

## If they ask to see it

1. Show 00-case-brief.md first. Read it aloud.
2. Show 03-pair-bonus.md next.
3. Say one sentence: two people on your team would each hold half of this and only get the twist if they chose to work together.
4. Do not open 04 or 05 on a first call.
5. Do not explain the format.

## If yes

Ask, verbatim: "What would you need to see before you'd put a date on the calendar?"

Write down immediately after, in the manager's own words: the date, or the exact words of what they need to see.

## If no

Ask, verbatim: "What makes it not a fit?"

Log the answer verbatim. File it against one of the four kill criteria the same day.

The four kill criteria, from the Pilot Manager Conversations Question Guide, written before the calls so they cannot be softened later:

- [ ] Budget and authority. If managers at this size consistently cannot commit spend for their own team without a process above them, the buyer is wrong and the segment reasoning changes, not the pitch.
- [ ] The free substitute. If free resources are working fine for their teams, the same hole that sank the consumer version is present here.
- [ ] The team unit. If most say their people figure things out individually, the coordinated unit premise is weaker than assumed and ops and GTM need re-examining, not defending.
- [ ] The date. The single hardest signal. If nobody commits to a date after the full conversation, nothing gets built.

## Never say

- **Hackathon.** This is a case, not a competition; say "working session" instead.
- **Buildathon.** Same drift as hackathon: it promises a build event, not a case discussion.
- **Platform.** One team gets one scenario pack; there is no infrastructure being sold here.
- **Leaderboard.** Team standing is group only. No pack scores or ranks a person.
- **Falling behind.** Banned in every pack; anchor the pitch on the manager's own deadline, not a race against peers.
- **Productivity gain.** No pack promises a number before the pilot runs. Point to the pilot and the measurement it names instead.

## After

Write it up the same day, while the manager's exact words are still fresh.

Append one line to rounds/manager-log.md with these fields, in this order: date, company, function, headcount, outcome (yes, no, or maybe), verbatim need-to-see, contamination flags (any banned word or feature-pitch language that slipped out on the call).
