Sociaily Case Engine

Operating Guide

Intake in, scenario pack out. A standalone Node tool. September 2026.

This turns one manager's intake record into a complete scenario pack for a single Sociaily team event: the case brief, two staggered partner tracks, the optional pair bonus, the ninety minute main event with gated exhibits and injections, the facilitator notes, and the retrospective with a revised SOP. It runs as one command and writes seven markdown files to disk. It is the plumbing that makes the tailoring claim real and gives you a draft to rewrite by hand for session one. It is not a website, a database, or a deployed app.

1. One-time setup

You need Node 20 or newer and your personal Anthropic API key. The key is read from a local .env file that is never committed. Never use the shared Sociaily key here.

cd ~/Projects/Demo
git checkout claude/git-branch-creation-dhyd08
echo 'ANTHROPIC_API_KEY=sk-ant-your-real-key' > .env
npm install
The key is not your Claude login. It is a separate API key from console.anthropic.com, billed per use. The .env file is already in .gitignore, so it stays on your machine and never reaches GitHub.

2. The everyday loop

Three moves: point at an intake, generate, check. For an existing intake:

node generate.mjs intake/acme-ops.json
node check.mjs out/acme-revops

What you should see: the seven files stream to the screen, then stop_reason: end_turn, a line reading Wrote 7 files to out/<slug>, a dash-replacement count (ideally 0), and an elapsed time under about ninety seconds. Then check prints PASS. The output folder is named from the team name, so "Acme RevOps" writes to out/acme-revops, not out/acme-ops.

A dry run assembles the full prompt without spending anything, useful for inspecting what the model will receive:

node generate.mjs intake/acme-ops.json --dry-run
# writes out/<slug>/_prompt.md, makes no API call

3. Where things live

PathWhat it is
generate.mjsThe engine. Reads an intake, assembles the prompt, makes one call, writes the pack.
check.mjsThe gate. Passes or fails a pack against structure, banned words, tool fidelity, the pair mechanic, dates, and case shape.
prompts/case-method.mdThe system prompt. The case-method rules and the output contract. This is the product; edit it to change how every pack reads.
intake/schema.mdThe field list, each mapped to the question you ask a manager on the call.
intake/*.jsonOne record per team. acme-ops and northwind-gtm are the worked examples; harbor-ops is a third test team.
examples/The two hand-written gold packs, fed to the model as few-shot so new packs read like your voice, not a generic exercise.
out/Generated packs. Gitignored, local only.
demo.mdThe run sheet for the last five minutes of a manager call.
rounds/Build reports and the manager log.

4. Making an intake for a real manager

Copy an existing file in intake/, rename it after the company, and fill in what you learned on the call. Every field maps to something the manager can answer. The full mapping lives in intake/schema.md; the fields that carry the most weight:

FieldWhat it holds
functionops or gtm. This picks which gold example the engine uses as its model.
stackThe exact tools on the team's seats. The pack may name only these. Nothing else.
sopName, sopSummaryThe current pre-AI workflow, in three to six sentences. This is what the case is built around.
painThe manager's own one sentence. Use their words, not a paraphrase.
deadlineWhat changes and by when. This is the case's clock.
closedLeversOptions the manager has already ruled out, each with a reason. These become the levers the pairs cannot pull.
pairs, tiersWho partners with whom, and whether each person is cautious or confident. Tier shapes the scaffolding, not the brief.
eventDate, leadUpStartThe Monday of the event and the Monday the lead-up week starts.
Two rules that decide whether a pack is any good. Every tool named in the pack comes only from the stack. And the pain, the deadline, and the workflow are the manager's, grounded by name. If a pack could be any company's, it failed, even if the gate passed.

5. The seven files

FileWhat it is and how you use it
00-case-brief.mdUnder 120 words. The protagonist, the decision, the deadline. This is what you read aloud first on a call.
01-partner-a-unlocks.mdFour dated unlocks for the confident partner, starting on the first lead-up day.
02-partner-b-unlocks.mdThe cautious partner's four unlocks, starting one day later so the pair has a reason to talk.
03-pair-bonus.mdThe optional edge. The twist that only appears when both halves are combined. This is the second thing you show on a call.
04-main-event.mdThe full ninety minute session: timeline, two gated exhibits, two injections, and the closing stand.
05-facilitator.mdYour side. What to release when, what to say to closed levers, the agent hint budget, the process rubric.
06-retro-and-artifacts.mdThe retro, the reasoning card per pair, and the revised SOP skeleton. The revised SOP is the adoption evidence the manager keeps.

6. The gate

node check.mjs out/<slug> reads pass or fail so a generic or off-brand pack is caught by a script, not by a manager's face. It checks seven things: the seven files exist and are long enough, no banned words (hackathon, leaderboard, and the rest), no em dashes in prose, every tool named is in the intake, the pair twist did not leak into one half, the case shape is intact, and the unlock dates fall in the lead-up week with B starting after A. It prints every failure with a file and line, not just the first.

When a real generation fails the gate, fix the prompt, not the gate. Open prompts/case-method.md, add the one rule that would have prevented the failure, and regenerate once. The gate is the ground truth. The only time you touch check.mjs is if it disagrees with the hand-written gold packs, which are the real standard.

7. The model

The engine defaults to claude-sonnet-4-6. To run a different model for one generation, set the MODEL variable without editing anything:

MODEL=claude-sonnet-5 node generate.mjs intake/acme-ops.json

8. The five minute demo

The full run sheet is demo.md. The shape of it: before the call, generate a pack from what you know of their stack, or use the matching sample pack if you know nothing. Then, in the last five minutes, say the two sentences and stop talking. If they ask to see it, show the case brief, read it aloud, then show the pair bonus and say one sentence about it. Do not open the main event or the facilitator notes on a first call, and do not explain the format. If yes, ask what they would need to see before putting a date on the calendar. If no, ask what makes it not a fit and log the answer against the four kill criteria the same day. Never say hackathon, buildathon, platform, leaderboard, falling behind, or productivity gain.

9. When something goes wrong

SymptomWhat to do
Fewer than seven files writtenThe engine prints stop_reason. If it is max_tokens, the pack was cut off. If the model changed the separator format, the split failed. Regenerate once; if it repeats, the gold example may be making the prompt too long.
Passes the gate but reads genericRead the generated brief next to the gold brief. For every sentence that could be any company, find the intake field that should have grounded it and add a rule to the prompt forcing that field by name. Regenerate once.
Gate fails on a hand-written exampleThe examples are ground truth. The check is wrong, or the example has a typo. Fix the check, not the pack, unless it is an obvious typo.
A dash slipped throughRe-run the dash cleanup on an existing pack without a new API call: node generate.mjs --reprocess out/<slug>.

10. What this is not

This is the engine and nothing more. There is no interface, no database, no login, no deployment. The visual prototype for showing a manager, and the between-sessions event surface with unlock timers and artifact posting, are separate builds. Per the project's own rule, the event layer waits until a manager has committed to a date. Keep this tool small and let it stay the thing that makes the tailoring true.
